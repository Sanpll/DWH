## 2. DAG и расписание

Реализован DAG `user_campaign_scd2_daily` с двумя зависимыми задачами:

1. `build_user_scd2` — построение снимка истории профилей SCD2.
2. `build_campaign_recipients` — расчёт получателей рассылок по соответствующему снимку SCD2.

Вторая задача запускается после успешного завершения первой в рамках того же DAG run. Для DAG настроены ежедневные суточные интервалы в 00:00 UTC, `catchup=True`, `max_active_runs=1` и автоматическая повторная попытка при ошибке.

По результатам запуска Airflow и Run ID, сохранённым в таблицах, созданы три scheduled-запуска:

| Run ID | Тип | Интервал UTC | SCD2 | Recipients |
|---|---|---|---|---|
| `scheduled__2026-01-23T00:00:00+00:00` | scheduled | `[2026-01-23, 2026-01-24)` | success | success |
| `scheduled__2026-01-24T00:00:00+00:00` | scheduled | `[2026-01-24, 2026-01-25)` | success | success |
| `scheduled__2026-01-25T00:00:00+00:00` | scheduled | `[2026-01-25, 2026-01-26)` | success | success |

Для окончательной сдачи к отчёту следует приложить скриншот или экспорт Airflow, показывающий тип запуска, Run ID и состояния обеих задач.

### 4.3. Физический план и стратегия JOIN

Для даты 2026-01-23 получен следующий физический план Spark:

```text
AdaptiveSparkPlan
+- BroadcastHashJoin Inner BuildRight
   :- Filter
   :  +- Scan parquet
   +- BroadcastExchange
      +- Project
         +- Filter
            +- Scan csv
```

Используется `BroadcastHashJoin Inner BuildRight`. Правая сторона соединения — таблица рассылок — передаётся через `BroadcastExchange`. Такая стратегия выбрана потому, что таблица рассылок существенно меньше исторической таблицы профилей. План подтверждает, что Spark применил broadcast-соединение. Сравнение производительности нескольких стратегий в рамках задания не выполнялось и не требуется.

## 5. Метаполя

В обеих результирующих таблицах присутствуют шесть обязательных метаполей:

- `_dag_id`
- `_run_id`
- `_task_id`
- `_data_interval_start`
- `_data_interval_end`
- `_loaded_at`

Проверка метаполей выполнена для шести партиций: двух таблиц (`user_scd2` и `campaign_recipients`) для каждой из трёх дат.

Для всех шести партиций установлено:

- строк с NULL хотя бы в одном метаполе — 0;
- строк с некорректными границами интервала — 0;
- `min(_loaded_at) = max(_loaded_at)` внутри каждой партиции.

Идентификатор DAG во всех результатах — `user_campaign_scd2_daily`. Значения `_run_id`, `_dag_id`, `_data_interval_start` и `_data_interval_end` совпадают между двумя задачами одного запуска. `_task_id` соответствует задаче, сформировавшей таблицу.
